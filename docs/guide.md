# mcbot 同伴桥接 · 使用指南

这个插件把本机的 **mcbot**（Minecraft 里的假人同伴）接进 N.E.K.O.。装好之后，
你可以让猫娘指挥同伴做事、替同伴转达问题，并听到同伴的阶段进展。

桥只在本机回环地址上运行，而且**只在 Minecraft 客户端进入某个世界时存在**。
所以“未连接”通常不是坏了，而是 Minecraft 没开、还停在主菜单，或者刚退出世界。

---

## 1. 准备

需要以下三样东西，缺一不可：

1. **Minecraft Java 1.21.11 + Fabric Loader 0.19.5 + Fabric API 0.141.6+1.21.11**。
2. **mcbot 本体**：把当前构建的 `mcbot-0.1.0.jar` 放进这个客户端的 `mods/`。
   必须和 N.E.K.O. 在同一台机器上；桥只服务本机。
3. **N.E.K.O.**：支持插件市场的版本。

一台机器同时只建议开一个带 mcbot 的 Minecraft 客户端：默认桥端口是 `17897`，
多个客户端会抢同一个端口。确实要开多个时，见下面“端口冲突”。

---

## 2. 安装插件

1. 在 N.E.K.O. 的插件市场安装 `mcbot_bridge`，或导入当前的
   `mcbot_bridge.neko-plugin` 包。
2. 打开插件，先确认它是**手动启动**（`auto_start = false`）。
   这样不会在 Minecraft 还没开的时候反复连接失败。
3. 如果 Minecraft 不在默认游戏目录，在插件设置里填 `game_dir`：
   - 填**包含 `mcbot/bridge.token` 的那个 Minecraft 运行目录**；
   - 常见是启动器的 `.minecraft` 目录，或版本隔离实例自己的目录；
   - 找不到时也可以直接把 `token_file` 指向 `bridge.token` 的完整路径。
4. `base_url` 默认 `http://127.0.0.1:17897`，一般不用改。
   只有你在 mcbot 的 `client.json` 里改过 `bridge_port` 时才需要一起改。

---

## 3. 第一次连接（顺序很重要）

1. **先启动 Minecraft**，进入一个世界。进世界后 mcbot 才会启动桥，并在
   `<游戏目录>/mcbot/bridge.token` 生成令牌。
2. 在游戏里打开 mcbot 的 G 面板（默认 `G`），确认能看到桥端点。
   需要核对令牌时，面板可以复制它；不要把令牌发给别人。
3. **再启动/启用本插件**。打开插件面板，点“刷新”。
   状态应该从“未连接”变成已连接，并显示当前同伴名字。
4. 如果还没有同伴，先在 mcbot 面板召唤一个同伴，再刷新一次。

> 进世界 → 桥启动 → 插件连接。反过来先开插件也可以，它会每 5 秒重试，
> 但第一次配置时按上面的顺序最容易判断问题出在哪一步。

---

## 4. 第一次指挥

先问一句“同伴在干嘛”，确认状态能回来。然后可以给一个简单任务：

> 让同伴去挖点木头。

猫娘会把任务交给同伴。你不需要自己拆步骤；同伴会扫描、选工作位置、移动、
挖掘和拾取，完成后把实际结果带回来。工具回执会以进度/HUD 的形式出现，
不需要每一条都念出来。

如果同伴正在忙，插件会提示“她正忙着”，不会把两个任务叠在一起。
等当前任务结束，或先停止当前任务，再派新的。

---

## 5. 你会看到什么

| 类型 | 表现 | 说明 |
|---|---|---|
| 进度 | 面板/HUD 短句 | 工具回执和中间阶段，不一定每条都播报 |
| 反问 | 猫娘转达一个问题 | 同伴拿不准时会问；你正常回答即可 |
| 关键节点 | 猫娘播报阶段成果 | 例如材料采集阶段完成；**不是整项任务完成** |
| 完成 | 猫娘汇报结果 | 只有 `completed` 算正常结束；失败会明确说没成 |
| 停止/被替换 | 不主动播报 | 你主动停掉或改派时，猫娘知道，不会重复播报 |

> `completed` 只表示任务正常结束，不等于每项自然语言目标都被独立验证；
> 是否真正达到目标，以猫娘汇报的实际成果和现场事实为准。

### 反问与路线授权

如果同伴要改动世界或路线，可能会先问你是否批准，并给出具体清单。
这时请按提示回答**一个明确的确认词**（例如“确认”），不要只回“就这个路线”；
mcbot 的授权匹配只接受固定的肯定词。回答后同伴会继续原任务。

### 叫停与接续

- 说“停下/取消”或点面板的“停止任务”，会停止当前任务。
- `目标状态`：查看当前保留的长期目标或已叫停建筑资料。
- `恢复目标`：恢复长期目标；`放弃目标`：放弃原记录。
- 如果刚叫停的是一栋**已登记的建筑**，还可以说 `继续` / `继续建造` / `继续施工`。
  只有在这种叫停建筑存在时，这三个词才是接续命令；平时“继续”就是普通任务。
  接续会重新核对身体、世界和新权限，不会回放旧动作、旧路径或旧批准。

## 6. 常见问题

### “未连接”

先看 Minecraft 是否已经进入世界。桥在退世界时就关闭了；主菜单、单人暂停界面
或刚启动客户端都可能是未连接。进入世界后等几秒，再点插件面板的“刷新”。

### 一直提示找不到 token

- 确认已经**至少进过一次世界**；
- 确认 `game_dir` 指向的目录里确实有 `mcbot/bridge.token`；
- 版本隔离/便携启动器请填实例自己的运行目录，不要填启动器安装目录；
- 实在找不到就把 `token_file` 直接指向 `bridge.token`。

### 端口冲突

默认 `17897`。如果本机已有其他程序占用，或你同时开多个客户端：

1. 在 mcbot 的 `client.json` 里设置 `bridge_port`；
2. 把本插件的 `base_url` 改成同一个端口，例如 `http://127.0.0.1:17898`；
3. 重新进世界，让桥在新端口启动。

### 插件面板空白

当前包的面板使用 `[[plugin.ui.panel]]` + `mode = "hosted-tsx"`。
如果面板空白，先确认安装的是**当前构建的包**，不是旧包；旧包的面板声明和端口都不同。
仍空白时，在插件详情页重新 Reload 或重装当前包。

### 任务很久没有结果

长任务可能持续几分钟。插件有等待预算；超时后只会告诉你“结果未知、可能还在跑”，
不会自动重发。先看面板状态或问一句“同伴在干嘛”，不要连续重派同一个任务。

### 为什么没有画面/截图

mcbot 的桥是任务级的，不提供截图或视觉上下文。本插件也没有这条能力。
它能做的是投递任务、转达反问和播报进展。

---

## 7. 隐私与安全

- 桥只监听 `127.0.0.1`，令牌只从本机 `bridge.token` 读取，不写进插件配置。
- 不要把 `bridge.token` 发给别人，也不要贴到聊天/日志/截图里。
- 插件日志只记录任务编号、长度、状态码等元数据，不记录任务原文、回答或问题正文。
- 同伴的模型 API key 只属于 mcbot 客户端，本插件不接触、不转发。

---

## 8. 停用与卸载

在 N.E.K.O. 插件面板停止/禁用本插件即可。它不会删除 Minecraft 世界、mcbot 配置、
同伴名册或令牌文件。需要彻底移除时，再按插件市场的卸载入口删除插件包。

---

## 9. 版本

- 本插件：`0.1.0`
- 桥接契约：`v1.0`（`contract_version`）
- 如果连接器发现桥不是 `1.0`，会按“旧版兼容”处理并提示，不会当作 v1.0 验收通过。
- 详细接口、配置项和开发说明见仓库根目录的 `README.md`。
