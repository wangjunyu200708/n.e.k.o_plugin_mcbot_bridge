# 桥接插件可靠性改进

日期：2026-10-25。下方为0.2.0实现记录，当前入口规则以本节及README为准。

0.3.1新增宿主后台可见的任务与回答入口。新任务仅由普通mcbot_task入口提交，
不再同时提供同名对话工具，避免两个模型重复下单；其余原任务槽、提交/取消串行锁、
未知结果保留、可靠通知、原始指令与角色关联机制继续复用。
成功受理返回实际游戏编号并静默完成派发入口；不会把派发成功当成游戏目标完成。
对话侧仍有mcbot_ask/answer/cancel三个控制工具，后台状态、回答、停止也有普通入口。
须启用宿主后台任务/用户插件能力。真实游戏和语音仍需新版插件联调。

## 范围

在现有插件上完善任务传递与沟通。宿主代码、mcbot 源码、参考项目和游戏实例保持不动。
没有安装插件、启动宿主/游戏或调用真实模型。测试不读取玩家 token 或模型配置。

角色分工保持：宿主猫娘负责用户交流，mcbot 负责游戏规划与执行，插件维护任务传递、
状态观察和反馈。不会把插件内部定时器当成游戏完成、死亡、停止或目标成功证明。

## 任务状态

- `claimed`：已占用插件任务槽，尚未提交。
- `submitting`：准备或正在提交。先保存本地记录，再发送 POST。
- `running`：取得有效的正整数 task_id；实际是否排队或挂起仍看观察。
- `unknown`：提交结果不确定、等待超时、重载或事件缺口，仍保留任务关联和叫停能力。
- 明确 completed/failed/cancelled/superseded 后按任务编号结算；completed 不自动表示目标成功。

明确的 400/401/413 及无法建立连接可以释放未受理任务。
请求超时、传输故障、500、畸形受理回执则保留未知，不自动重发。
取得编号前的 done 和 question 有限暂存，取得编号后再处理；未知编号不认领其他任务的 done。

真实宿主工具入口通过同一异步锁串行提交和取消，避免停止先于仍在途的 POST 到达。
取消即使本地没有任务也发送原 cancel-all 请求；成功回执只代表客户端接受取消，
不承诺服务端身体已经停稳。未知取消不降级为成功，也不自动重试。

仍保留单个插件派发任务槽。游戏中已存在的任务会阻止新增工作，防止插件重载或
恢复命令结束后误以为游戏空闲。缺失状态字段不解释为零。
无法关联的既有游戏任务不会被猜成插件自己提交的工作。

## 观察与汇报

`mcbot_ask` 工具保留原名称和 text 参数，但现在仅做 GET status 加本地观察读取。
不会调用会创建游戏任务的兼容 REST `/v1/ask`。返回执行状态、观察时间、最近工具回执、
待答问题和有限结果记录。工具回执不是新的背包快照，也不是整个目标的验收。

这意味着“你挖得怎么样了”不会打断 PARK 或追加游戏任务；
但不能用这条只读查询取得桥未提供的实时背包或位置。需要新的游戏观察时，
应由用户明确交代合适的任务，不能由插件为了填补缺失事实自行派活。

completed 使用中性的结果回执模板，保留原文的未完成、受阻和未知限定；
failed 保留原因及已做部分。模板不自行宣称身体已经停止。
缺失或未知 status 保持未知，不冒充 completed，不妨碍稍后合法终态结算。

“恢复目标”“目标状态”“放弃目标”“继续”“继续建造”“继续施工”均使用命令回执。
恢复后新执行任务可以从状态/SSE 观察并用原取消入口叫停。
v1.0 没有 parent_task_id，插件不凭两个编号推定精确父子关系。

## 通知

完成、失败、问题及超时等 respond 通知按独立合并键进入有限待送记录。
调用真实 SDK 形状的 push_message 后，只有 `submitted=true` 才确认本地提交；
返回拒收、没有回执或抛异常都会保留待送。后台每两秒尝试补送。
问题终止、回答、过期或换会话后不再补送；授权清单不裁剪。
payload_too_large 保留完整通知并标为阻塞，不反复发送相同超限载荷。
待送队列满时不消费新重要事件，保留原 SSE 游标供后续补发。

SDK 接收并非宿主消费、模型回复或语音播放确认。
进程在接收与落盘之间崩溃仍可能重复通知；没有端到端 exactly-once 或持久游戏事件队列承诺。
普通进度沿原 HUD/合并策略，不让每一步工具成功都触发猫娘开口。

## 持久记录与隔离

本地 data/runtime.json 通过临时文件加原子替换保存：
当前任务、问题、有限历史/进展、任务角色、终态/事件去重及待送通知。
data/cursor.json 保留会话与已处理 SSE 游标，客户端完成消费者处理后才更新它。
发现编号缺口时保留未知观察；不能由 status 的空闲计数反推历史成功。

重载只恢复观察，不重放 POST、答案、批准、游戏路径或程序。
同会话保留任务；新会话将旧任务记未知、清旧问题和指令映射。
本地记录损坏时不覆盖原件或派新工作，面板提供 storage_error。
应保留问题文件诊断后再由维护者处理；不能拿删除记录冒充停止游戏任务。

有宿主角色信息时，从 NekoPluginBase 保留的原始 host context 读取当次调用角色，
而非从模型参数或最近调用者推断。问题、任务和结果沿该角色关联。
无法取得角色时兼容原单角色行为；本轮不宣称完整多用户权限系统。

桥地址仅接受回环 HTTP；凭据不进入 URL。传输不使用系统代理环境变量，
避免本地任务通信经代理转发。运行依赖明确声明 httpx。

## 验证

测试分三类：

1. 原有单测和新增任务回归：受理未知、迟到回执、超时叫停、提交与取消顺序、
   观察不派活、恢复别名、角色归属、重载恢复、通知拒收/超限和持久化故障。
2. 实际 McbotClient 与 httpx.MockTransport：POST task、提前 SSE 问题、
   POST answer、SSE done 的闭环；没有真实网络、游戏和模型。
3. 只读加载可用宿主源码中的工具元数据与 push_message 翻译函数，
   检查四个工具及指定角色通知的真实格式；不启动宿主进程。

宿主源码可通过 NEKO_HOST_SOURCE 指定；缺失时只跳过对应宿主专项。
面板另用 tools/check-panel.cjs 对照可用宿主的 hosted UI 声明进行类型检查。
最终测试结果和产物指纹见根目录 STATUS.md。
