# mcbot 与猫娘对接测试

适用桥接器 0.3.2、配套新 mcbot 0.1.0。此次自动阶段汇报逻辑在游戏JAR中，
由0.3.0/0.3.1升级也需要更换JAR；文件名与模组版本保持不变，以本次交付哈希区分。

## 安装游戏模组

1. 退出游戏，在所启动版本的独立游戏目录 `mods/` 中替换旧 mcbot，
   只保留一个 `mcbot-0.1.0.jar`。保留原来的 `mcbot/` 配置目录。
2. 使用 Minecraft 1.21.11、Fabric Loader 0.19.5、Java 21；
   需要 Fabric API 0.141.6+1.21.11。多人服务器也安装同版 mcbot 和对应依赖。
3. 启动游戏进入世界，按 G 配置并启用 mcbot 大脑，召唤自己的同伴。
   已有可用大脑配置可继续使用。先确认 G 面板里直接发简单指令能够执行。
4. 在 G → 设置 → 通用核对任务桥端点，默认 `http://127.0.0.1:17897`。
   首次进入世界会产生 `<游戏目录>/mcbot/bridge.token`。

## 导入宿主插件

1. 打开 N.E.K.O 插件管理，使用本地包导入入口选择
   `mcbot_bridge-0.3.2.neko-plugin`，按页面完成导入。
   不需要解压。已有同 ID 插件时先停止它，使用宿主提供的更新或替换流程。
   若仅能改名安装，先停用旧副本，避免同时派活。
2. 打开 MCBot 同伴桥接的配置表单：

   | 字段 | 填写内容 |
   | --- | --- |
   | `base_url` | G 面板任务桥端点，默认 `http://127.0.0.1:17897` |
   | `game_dir` | 启动器实际使用的独立游戏目录，里面应有 `mods`、`logs`、`mcbot` |
   | `token_file` | 通常留空，自动读 `<game_dir>/mcbot/bridge.token`；也可明确填该文件路径 |
   | `stream_events` | 开启，任务进展、问题和结果依赖事件流 |
3. 保存配置，启用并手动启动插件。此包默认不自动启动。
   若插件已经运行，保存后停止再启动，以使用新配置。
4. 打开插件的 mcbot 同伴面板，刷新状态。确认桥已连接、契约为 1.0、
   大脑已启用、身体存在。连接正常但没有身体时，回游戏召唤同伴。
5. 开启宿主后台任务分析器和用户插件能力。`mcbot_task`必须出现在插件普通入口中，
   由后台识别用户请求后调用；对话模型不必亲自调用游戏派发工具。
   对话工具仅保留进度查询、回答、停止；后台也有状态、回答、停止及配置重载入口。
   测试时停用其他 Minecraft 桥接插件，避免派错执行端。

宿主对话模型负责与你沟通，游戏里的 mcbot 大脑负责规划和执行。
两边都需要各自可用的模型配置；桥接的 `base_url` 是本地游戏端点，
`bridge.token` 是本地鉴权文件，都不是模型 API 地址或 API key。

## 测试顺序

1. 对猫娘说：“看看你在 Minecraft 里的身体是否在线，先别派任务。”
   应读取状态，游戏里不产生新工作。
2. 说：“去采集 2 个橡木原木，完成后告诉我实际结果。”
   应先简短确认接收，然后游戏里的同伴行动，结束后猫娘按实际回执汇报。
   测试场地应有可达橡树和可用工具。
   接单应说“我去做”，不要把采集转交给用户。重载配置和查询成功不应播报成游戏任务完成。
   真正结束时应说明采集物品与实际数量，不能只说“行动任务完成”。
3. 执行期间正常聊天，再问：“现在进度怎么样？”
   应继续原任务并读取观察，不重新派发相同工作。
4. 若游戏请求许可，猫娘应转述；明确回答同意或拒绝后，只处理当前有效问题。
   是否启用自主动作由你在 G 面板决定，桥接不修改这项设置。
5. 发一个较长任务，再说：“停止 Minecraft 任务。”
   核对游戏真实停下，插件面板也能停止任务。取消回执不代替身体停稳观察。
6. 基础链路跑通后，再测“挖一颗钻石”和“跟着我，有敌人时保护我”。
   钻石任务还依赖工具、地形和资源，受阻时应报告原因，不能把受理说成完成。
7. 测试关键节点：“帮我做一把钻石镐，每完成重要阶段就告诉我，然后继续做。”
   按现场已有条件规划；缺工具时应在工具准备好、关键资源入包等节点主动汇报，
   最后才汇报整项结果。已有铁镐不应机械退回木镐流程，木板/木棍/每次查询不应逐条播报。
   再换成采料建造或准备其他装备，核对相同机制复用；中途正常聊天不应重派或停止游戏任务。
   模型选点和真实语音仍须联调，不承诺每条任意路线必然选中全部期望节点。
   新JAR会自动汇报gather材料子目标满足、craft工具/耐久装备实际入包，不必模型记得调用。
   木板/木棍等中间合成不会逐项播报；重要位置/建筑阶段仍由模型选择可核实条件。
   猫娘播报期间游戏应继续执行，不等待语音结束；同资源/工具在同任务不重复自动播报。
   插件日志milestone delivery=submitted只说明宿主SDK受理，queued表示等待可靠补送。

## 排查

| 现象 | 检查 |
| --- | --- |
| 连不上桥 | 是否已经进入世界；G 面板的任务桥端口是否与插件一致 |
| 找不到 token 或鉴权失败 | `game_dir` 是否指向真正的独立实例；显式 `token_file` 是否指向别的实例 |
| 插件连通但不行动 | 大脑是否启用、模型是否可用、同伴是否已召唤、是否在等许可 |
| 猫娘只口头答应 | 后台任务/用户插件是否开启；普通入口是否包含 `mcbot_task`；是否仍运行旧版插件 |
| 游戏完成但猫娘不汇报 | 插件是否仍运行、事件流是否开启、面板是否已收到终态、待送通知是否积压 |
| 换世界后显示旧任务未知 | 这是会话隔离；确认新身体与状态后重新明确下达任务，不会自动重发旧动作 |

反馈问题时记录时间、原指令、插件面板状态和两侧日志。游戏日志位于实例 `logs/`。
Steam 版宿主日志通常位于 `%LOCALAPPDATA%/N.E.K.O/logs/`，
桥接插件日志在其 `plugin/` 子目录。以宿主启动日志报告的实际目录为准。
不要发送 `bridge.token` 内容或含 API key 的配置文件。

本交付经过离线构建、测试与正式包检查；真实游戏、宿主模型路由和语音反馈仍需上述联调。
